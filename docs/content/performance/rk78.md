# Adaptive RK7(8): results

The RK4 oscillator above is a fixed-step problem: every accepted step costs
the same arithmetic, and the four friction points (launch overhead, host
round trips, finished samples, idle lanes) show up against a constant
per-step cost. The second card runs the same class of problem through an
*adaptive* solver instead: a two-body Kepler orbit (float64, eccentricity
uniform in [0, 0.9]) integrated with Fehlberg's embedded RKF7(8) pair to
rtol = atol = 1e-10, so each sample also decides, step by step, whether to
accept or shrink -- a second, data-dependent source of per-sample
divergence on top of each sample's own stopping time. `eagle.simulate`
appears here too, running the same attempt kernel the hand-built `hawk + eagle
graph` arm uses, under its automatic launch policy.

Pick a device with the tabs; the table of every arm and every N is collapsed
under the chart. How to read the numbers: [Reading the numbers](reading.md).

`attempt_kernel` in the same file turns any such tableau into the one-attempt
hawk kernel the RKF7(8) arms run (same step-size controller, same accept or
reject per sample), and `eagle.until_done` runs it as before.

On 10,000 of the same orbits at rtol = atol = 1e-9, both pairs finish within
2e-6 of the analytic orbit. Dormand-Prince takes 1,270 accepted steps on
average per orbit (3 rejected), RKF7(8) takes 314 (77 rejected), so the
lower-order pair does about four times the attempts but each is 7 stages, not
13: on a Quadro P2000 the run takes 0.27 s against 0.18 s for RKF7(8), and on
8 CPU threads 3.5 s against 2.1 s. Median of three runs, a demonstration on
this one problem, not a card.
